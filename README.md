# DuckDB + PyArrow + Parquet playground

A tiny, self-contained Python project for experimenting with **PyArrow** (columnar in-memory tables), **Parquet** (columnar files), and **DuckDB** (SQL analytics). No database server, pandas, or external data is needed.

## Requirements

- Python **3.11+** (or let `uv` install a compatible version)
- [`uv`](https://docs.astral.sh/uv/getting-started/installation/)
- `make` (optional; you can use `uv` directly)

## Quick start

Open a terminal in this project folder and run:

```bash
make setup   # uv sync: creates .venv and installs duckdb + pyarrow
make run     # uv run python main.py
```

**Without Make:**

```bash
uv sync
uv run python main.py
```

If Python 3.11+ is not installed locally, you can first run `uv python install 3.13`.

## What the script does

1. Constructs a typed `pyarrow.Table` of sample orders.
2. Writes `data/orders.parquet` with PyArrow using Zstandard compression.
3. Queries the Parquet file directly with DuckDB SQL.
4. Registers an in-memory Arrow table and queries it with DuckDB.
5. Converts query output back into an Arrow table.
6. Writes aggregated query results to `data/customer_summary.parquet` using DuckDB.
7. Shows DuckDB's `EXPLAIN` plan for a filtered Parquet query.

Running the script again overwrites the same generated files, so experiments are repeatable.

## VS Code debugging

1. Open **this folder** in VS Code.
2. Install the **Python** and **Python Debugger** extensions by Microsoft.
3. Run `make setup` (or `uv sync`) in the integrated terminal.
4. In VS Code, select the project's `.venv` interpreter using **Python: Select Interpreter** if it isn't selected automatically. On macOS/Linux choose `.venv/bin/python`; on Windows choose `.venv\\Scripts\\python.exe`.
5. Open `main.py`, set breakpoints, and press **F5**. Choose **DuckDB + Arrow playground** if prompted.

The launch configuration uses the project directory as its working directory, and `.vscode/settings.json` points Python tooling at `.venv`.

## Make commands

| Command | Purpose |
|---|---|
| `make setup` | Create/update `.venv` and dependencies |
| `make run` | Run the example |
| `make clean` | Delete generated `data/` files |
| `make reset` | Delete `data/` and `.venv/` |
| `make help` | Show available commands |

## Experiment ideas

- Modify the aggregation SQL to show **monthly revenue** (`date_trunc('month', ordered_at)`).
- Add a filter (`WHERE unit_price > 100`) and inspect the `EXPLAIN` output.
- Write several Parquet files and query them together with `read_parquet('data/orders_*.parquet')` (use a separate directory so the summary file isn't mixed with orders).
- Add `LIMIT`, `JOIN`, or window functions to the SQL.
- Replace the eight-row dataset with a million rows and measure performance.
